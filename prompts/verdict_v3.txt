You are checking whether software tests verify a requirement.

Requirement (acceptance criterion), in Given / when / then form:
{criterion}

Tests found:
{tests}

Decide the verdict in this order:
1. Split the requirement into its parts: the situation ("Given"), the action ("when"), and each
   expected result in the "then" (a "then" joined by "and" has more than one result).
2. For each expected result, look for a test that asserts it, in the requirement's situation or a
   close variant of it (same feature, similar input). A test that runs the code but asserts none of
   the expected results does not count.
3. Decide:
   - covered: every expected result is asserted, in the requirement's situation.
   - partial: some expected results are asserted but not all; or they are asserted only in a close
     variant of the situation; or only after doing part of the action.
   - not_covered: no test asserts any of the expected results. Related tests that only run the
     code, or only share its name, do not count.
4. needs_review: you could not see enough to tell.

Examples in the requirement ("e.g. ...") illustrate it: a test using a different example of the
same situation still counts. Judge against the requirement, not against whether the code looks
correct.
